# 本地 AI 角色（类 Neuro-sama）架构结论

> 2026-10-06 讨论的结论。**尚未动任何代码，也未确定要做**。下次想继续时从这里接上。
> 支撑事实见同目录 [`bionic-capability-research.md`](./bionic-capability-research.md)
> 与 [`dsh-programmatic-access.md`](./dsh-programmatic-access.md)。

---

## 一、目标形态

让手机 App 成为某个**本地 AI 角色**的窗口：用户在手机上跟它聊天，角色有稳定性格与长期记忆；
而**人格、记忆、上下文全部在本地跑**，App 只负责输入与显示，不参与状态。

与"本地 Agent 干活"的区别：前者是**持续活着的角色**，后者是**能干活的任务工具**。两者对架构的要求几乎正交。

---

## 二、载体结论：Bionic 出局

**原因**：Bionic 是封闭的 agent 宿主 —— 无 API、无 CLI、无 headless、无 MCP 服务端，
会话是本地 sqlite 不外露（官方 issue #2467 原话："sessions created on one machine are **stranded there**"）。
"Bionic 当人格层 + 手机远程接入"**今天不成立**。

⚠️ 最容易误判的一点：**它确实开着一个 OpenAI 兼容端口（1234），但那只是"模型推理口"，不承载 agent 会话。**
DSH 这边的对应物是 `sessionController`，不是 `/v1/chat/completions`。

Bionic 唯一还有用的形态是"模型推理后端"，但它与 LM Studio **共用 `~/.lmstudio/models`**，重复建设。

## 三、修正后的架构（全部落在 DSH 内）

| 层 | 落点 | 用什么 |
| :--- | :--- | :--- |
| **人格层** | 一个常驻 DSH 实例（独立 profile，端口与现有 3080 错开） | 微调的本地模型当对话模型 + 记忆文件 + preset 定人格 |
| **执行层** | 同上，或由人格层按需拉起的执行实例 | 云端大模型（本地跑不动的那个） |
| **窗口** | App + 中继 + 桥接 | **现成，一行不用改** |

**接法（推荐先试最省的那条）**：人格实例注册一个工具 `run_task(task)`，内部 spawn
`dsh --profile headless "<task>"`，拿 stdout 回来作为 tool result —— 结果回到人格模型的上下文，
由它用自己的声音讲给用户。**要写的只有一个几十行的插件**，零协议代码。

代价：每次执行付一次 runtime 冷启动。可接受就先不写 MCP。

---

## 四、三个必须记住的约束

1. **微调模型必须有 tool calling**，否则它连"调 `run_task`"都做不到，这条路线整条断掉。
   而且经验上：**微调后的轻量模型工具调用能力通常比基座更差** —— "有性格"和"可靠调工具"在权重上是打架的。
   所以别让它直接调一堆工具，只给它**一个**意图级工具（`run_task`）。
2. **人格内核与记忆必须分家**：人格内核在微调权重里（只有作者能改、要重训），记忆在本地文件里（它自己读写）。
   ⚠️ **会变的东西绝不能写进人格内核** —— 否则为了改一条记忆就得重训模型。
   记忆用**文件**而不是向量库：记忆是它人设的一部分，它得能自己看见、自己改；向量库是黑盒。
3. **安全边界不能混**：本机信任层（无鉴权的本地端点）与用户通道层（App 那条有鉴权的链路）
   **一个都不能经 Cloudflare Tunnel 或 `--host 0.0.0.0` 暴露出去**。

---

## 五、下次继续要解决的两个接缝问题

1. **"该说话"还是"该动手"由谁判断** —— 若靠人格层自己判断，轻量模型做结构化判断不可靠；
   最稳的起点是**只给一个意图级工具 + 规则硬分路由**，牺牲一点自然度换可控。
2. **执行结果怎么摘要回人格层** —— DSH 的长技术输出（工具输出、日志、diff）直接回灌会让小模型崩
   （要么复述细节、要么编）。中间那道摘要放哪一层，要定。

（`EventSource` 之外的实时性、TTS、事件循环等都还没进入讨论 —— 先把上面两条定了再说。）
