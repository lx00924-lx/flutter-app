## 记录格式（沿用即可）

每条至少写清四件事，否则下次还得重新摸一遍代码：

1. **要什么** —— 一句话说清最终效果；
2. **为什么** —— 用户的原话或实际痛点，避免下次凭感觉"优化"掉；
3. **现状定位** —— 文件 + 行号 + 关键函数名（**写行号时注明是哪天的代码**，
   行号会随改动漂移，函数名才是稳的）；
4. **怎么做 / 注意事项** —— 尤其是"别顺手把 X 也改了"这类边界。
